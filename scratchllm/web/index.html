Architecture & optimization

            

              

              

              

              

              

              

            

            

            

            

            

            

            

            

            

            

            

            

          

          
Generalization controls

            

            

            

            

            

            

          

          
Response-oriented defaults: 512-token context, 6 layers × 256 width, 2 × 8 microbatch/accumulation, shuffled sampling, and up to 25 data passes with validation-based early stopping. This keeps capacity modest for the current small corpus and doubles context. These settings are a starting point, not measured ChatGPT-level quality. Conversational instruction-following needs suitable human question/answer examples; raw articles and board posts teach their own writing styles.

          
          

          
Start creates random weights. A larger/newly prepared dataset requires Start in a fresh run directory. Resume uses the old run's saved dataset and budget, ignoring edited fields. Stop saves at the next optimizer boundary. Generation pauses during training to free GPU memory. After training, use Load checkpoint below to switch the playground.

          
          
        

        

          
04 / Prepare dialogue

          
Use a base checkpoint trained on Wikipedia and your selected sites. Its exact BPE vocabulary/token IDs are reused; no tokenizer is fitted here. Dialogue downloads contain human-authored text, with URLs removed.

          
          
          

            
            
          

          
          
          
Custom JSONL uses alternating user/assistant messages. Whole conversation/family groups stay together; each assistant reply becomes a training example. Only assistant response tokens receive loss. Select a native .pt checkpoint; imported Hugging Face models use their separate workflow.

          
          
          
Pinned exports are cached and checksum-verified. OASST model-generated/deleted/unapproved messages are excluded. Complete assistant responses must fit the base context; longer examples are reported as skipped. Attribution is saved with the dataset.

05 / Fine-tune a checkpoint

          
          
          
          

            

            

            

            

          

          
          
Starts from the selected checkpoint, preserving its architecture and vocabulary. Dialogue datasets use assistant-only loss; custom .txt datasets use next-token loss over all corpus text and retain the checkpoint's existing chat format. Plain text fine-tuning learns the text's writing style and content. Best-checkpoint selection uses held-out NLL. Early-stop patience: 3 checks. Resume restores the saved model, optimizer, data, and budget.

04 / Fine-tune the imported model

          
          
          
          

            

            

            

            

            

            

            

            

            

          

          
Trains adapters on next-token prediction over your site text. The base weights are frozen. FP32 computation and activation checkpointing suit the GTX 1050 Ti; QLoRA reloads the reconstructed base into NF4. Held-out NLL selects the best adapter; early-stop patience is 3 checks. Stop saves at an optimizer boundary; Resume restores the exact data and budget.
