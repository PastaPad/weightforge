# Offline Wikipedia with Kiwix

Selecting `wikipedia.org` now imports human-written articles from a local **ZIM** archive using `libzim`. Wikipedia collection does not browse Wikipedia, follow its links, execute JavaScript, or open a browser. Other selected websites use the existing Camoufox collector.

## Configured archive

- File: `data/kiwix/wikipedia_en_top_nopic_2026-09.zim`
- Official URL: `https://download.kiwix.org/zim/wikipedia/wikipedia_en_top_nopic_2026-09.zim`
- Title: **Best of Wikipedia**, English, dated **2026-09-14**.
- Size: **2,745,850,723 bytes** (about **2.56 GiB**).
- SHA-256: `8369b95b6b2179051b56ebed0d43fd3646020d03367eb03d7fc34d84090c501b`.
- Archive UUID: `65d4124b-2288-7c85-1e69-e675a5bbd288`.

This is Kiwix's broad “top articles” selection with full article text, **not all English Wikipedia**. Archive article-entry counts include many redirects and are not counts of usable training documents. `nopic` minimizes media in the archive; the importer reads HTML bodies only and excludes media/interface content from the corpus. The archive contains no model weights or pretrained tokenizer.

## GUI

1. Open **Data & training → 01 / Collect text** and select **Wikipedia (offline Kiwix articles)**.
2. Choose the local file above. **Refresh local archives** lists supported `.zim` files under `data/`; a workspace-local custom path can also be entered.
3. Set the vocabulary size and validation fraction in section **02 / Prepare dataset**.
4. Click **Whole ZIM → dataset**. This scans every entry in the archive, extracts eligible article text, fits the local tokenizer, and writes the train/validation files automatically. It finishes at the prepared dataset. Fresh corpus/dataset paths are generated by default; turn off the checkbox beside the button to use the paths from sections 01–02.

**Process the whole ZIM** is also enabled by default for ordinary GUI collection and the training pipeline. It removes the Wikipedia article cap; the page-attempt limit still applies to website sources. Turn it off for a limited Wikipedia sample. Text-only filtering, minimum lengths, and deduplication still apply across the whole archive.

The two-stage dataset job shows archive-entry progress, preparation logs, and output paths. Close/reopen the GUI freely. **Stop dataset build** stops the current stage; **Resume whole-ZIM dataset** restores its paths/settings and continues the saved archive cursor. Preparation publishes its output directory only after completion. If stopped during preparation, resume restarts preparation from the complete corpus. Finished datasets appear in the dataset selector.

To get another archive, expand **Download or update a Kiwix archive**. Load the current official catalog or enter an official English Wikipedia `.zim` URL. **Download / resume archive** starts a supervised download; **Stop job** retains the partial file. Click Download again with the same URL/path to resume. The complete SHA-256 and archive metadata must pass before a `.zim` file is published. The monitor displays download/verification bytes. Download completion does not launch collection or training.

## Collection behavior

- Uses a deterministic, constant-memory permutation of archive entry IDs, controlled by `wikipedia_seed` (default `42`). It spreads attempts across the archive instead of walking neighboring links. Whole-ZIM mode processes the entire permutation, streaming one article at a time rather than loading the archive's text into RAM. Limited mode is not topic-balanced sampling.
- Skips native ZIM redirects **and HTML refresh redirects** (often aliases to article sections), Main Page, utility namespaces, landing pages, non-HTML items, and items larger than 20 MB.
- Uses the same positive MediaWiki article extraction as the website collector: prose, headings, lists, quotations, code, and article data tables. Removes UI, media, references, link sections, infoboxes, and navigation. Unknown layouts contribute no text.
- Applies the existing URL-free text policy and normalized content deduplication. Ordinary hyperlink labels remain prose. Nothing is learned from scripts, styles, media assets, or archive metadata.
- Writes the existing `article-post-text-v4` JSONL format with `transport: "kiwix-zim"`. Each record retains its original Wikipedia article URL, group, title, archive path/UUID/checksum/date, and entry path. Only `text` is tokenized. Wikipedia contributors' attribution is accessible through the source article and its history; Wikipedia's applicable content license continues to apply.
- Imports Wikipedia before browsing any other selected sites. Website delay, depth, robots, and browser controls apply to the website stage.
- Saves the entry cursor, original seed/settings, archive identity, corpus digest, and counters in `<corpus>.crawl.sqlite3`. Corpus bytes are flushed before committing the cursor. Stop/resume and extending the total limit work with the existing GUI controls.
- Resume checks the archive UUID, internal checksum, size, modification time, and path. A capped Kiwix collection can be extended to whole-ZIM mode while keeping its cursor and original ordering. Keep the archive and corpus/state files in place. To change archives, use a fresh corpus. A legacy Wikipedia web queue also requires a fresh Kiwix collection; it is never silently continued by scraping.

## CLI

```bash
# Default download, with resumable .part file and verified .download.json receipt.
python -m scratchllm.kiwix

# Import every eligible article from the ZIM.
python -m scratchllm.crawl --hosts wikipedia.org \
  --wikipedia-zim data/kiwix/wikipedia_en_top_nopic_2026-09.zim \
  --wikipedia-seed 42 --wikipedia-all --output data/wiki-kiwix.jsonl

# Continue a stopped collection, or extend an older capped collection to the whole archive.
python -m scratchllm.crawl --output data/wiki-kiwix.jsonl --resume --wikipedia-all

# Fit a local tokenizer and prepare the normal grouped train/validation streams.
python -m scratchllm.prepare --input data/wiki-kiwix.jsonl \
  --output data/prepared-kiwix --vocab-size 8192 --atomic-output
```

These commands download/import/prepare data; model training uses its separate controls.

## API

- `GET /wikipedia/archives`: supported local files, metadata, and default paths.
- `GET /wikipedia/catalog`: latest text-only variants from the official Kiwix catalog.
- `POST /jobs/kiwix`: `{ "url": "https://download.kiwix.org/zim/wikipedia/<archive>.zim", "output": "data/kiwix/<archive>.zim" }`.
- `POST /jobs/zim-dataset`: a data-only two-stage job. An empty JSON object uses the configured archive and fresh output paths. Customize its nested `crawl` and `prepare` settings as below. Resume with the saved `job.settings`, `auto_paths: false`, and `crawl.resume: true`.
- `POST /jobs/crawl`: existing settings plus `"hosts": ["wikipedia.org"]`, `"wikipedia_zim": "data/kiwix/<archive>.zim"`, `"wikipedia_seed": 42`, and `"wikipedia_all": true` for a complete archive. The API defaults to limited mode when this flag is omitted.
- `POST /jobs/pipeline`: the same fields inside its `crawl` object. Download the archive first; a missing/invalid file is rejected before launching the pipeline.
- `GET /jobs` and `POST /jobs/stop`: existing supervision for both downloads and imports.

Example body for `POST /jobs/zim-dataset`:

```json
{
  "auto_paths": true,
  "crawl": {
    "hosts": ["wikipedia.org"],
    "wikipedia_all": true,
    "wikipedia_zim": "data/kiwix/wikipedia_en_top_nopic_2026-09.zim"
  },
  "prepare": {"vocab_size": 8192, "validation_fraction": 0.1}
}
```

For an unattended data-only CLI job, save this body in a JSON file and pass it to `python -m scratchllm.pipeline --dataset-only --request <file> --root <workspace> --progress-file <progress.json> --stage-state <stage.json>`. Direct coordinator requests use the corpus/output paths in the request; the web API resolves `auto_paths` before starting the coordinator.

The reader validates Wikipedia metadata and accepts English or Simple English archives. GUI/API paths must stay inside the workspace. The downloader accepts only official HTTPS English Wikipedia archive URLs. Partial downloads remain `.part` files until their SHA-256 matches the official `.sha256` sidecar and their metadata is readable.

## Verification

`test_kiwix.py` uses real tiny ZIM files to check extraction, namespace/redirect/media exclusion, attribution, deduplication, grouped reports, cancellation/resume, changed-archive rejection, download integrity/range resume, mixed website/ZIM collection, and real supervised imports. `test_zim_dataset.py` runs actual whole-archive import and tokenizer preparation with a one-article cap, exercises stop/resume in both stages, and verifies extension of old capped imports. Its worker guard permits only collection and preparation. `test_kiwix_ui.py` checks archive/download controls, whole-ZIM progress, the two-stage action, resume after reopening the GUI, and dataset selection. The existing three/five-stage browser checks carry the archive settings through the training pipeline. These tests perform no model training.
